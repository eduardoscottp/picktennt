# Registration before fixtures

Approved by the organizer in this chat on 28 October 2026.

Tournament configuration and registration precede match generation. Group seed inputs are capacity slots, not invented teams. Incomplete graph connections are missing decisions and must not prevent saving supported scheduling values. Publication requires the event, registration, policies, scheduling, registration node, entries node and group capacity plan; knockout connections can remain pending, clearly disclosed in review.

At roster lock the administrator supplies a complete supported graph when the published plan is unfinished and may explicitly assign approved entry IDs to group slots. Assignments cover each actual entry exactly once, respect group capacity and have at least two entries per initial group. Underfilled groups generate only occupied-slot round-robin games. No registration, scoring, consent or scheduling policies change during finalization. Existing node IDs/modules and supplied connections are preserved; missing connections can be completed. No fixtures exist before lock; duplicate/stale writes retain existing revision and receipt protections.

Automatic cross-group runner-up comparison remains unsupported. It is disclosed as pending and does not silently become winners-only or manual selection. A complete supported qualification plan is required before generation; changing registration timing alone does not implement that ranking feature.

Tests exercise draft preservation, publication without participants, pending-generation rejection, actual assignments, underfilled generation and completion, invalid rosters, permissions, persisted SQL state and existing graph regression behavior. No production tournament is edited by this work.
